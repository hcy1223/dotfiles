# Editor Dotfiles

This repository manages my local Neovim and VS Code configuration in one place.

The goal is simple:

- keep editor configuration versioned
- make changes easy to review with Git
- make a new machine restore predictable
- avoid committing editor caches, history, logs, and machine-local runtime data

## Repository Layout

```text
.
├── nvim/
│   └── mirrors ~/.config/nvim
├── vscode/
│   ├── User/
│   │   ├── settings.json
│   │   ├── keybindings.json
│   │   └── snippets/
│   ├── profiles/
│   │   └── optional manual .code-profile exports
│   └── extensions.txt
└── scripts/
    ├── sync-from-local.sh
    └── install-to-local.sh
```

## What Is Managed

### Neovim

`nvim/` mirrors:

```text
~/.config/nvim
```

The sync script excludes the nested Neovim Git repository and local log files.

### VS Code

Only stable user-level VS Code config is managed:

```text
~/Library/Application Support/Code/User/settings.json
~/Library/Application Support/Code/User/keybindings.json
~/Library/Application Support/Code/User/snippets/
```

Installed extensions are recorded in:

```text
vscode/extensions.txt
```

VS Code cache, history, logs, global storage, sync state, and workspace storage are intentionally not committed.

### VS Code Profiles

`vscode/profiles/` is reserved for optional `.code-profile` files exported from VS Code's Profiles UI.

These files are not generated by `sync-from-local.sh`. Export them manually from VS Code when needed:

```text
Profiles -> Export Profile... -> Local File
```

Use profiles as portable snapshots for a whole VS Code profile. Use `vscode/User/settings.json`, `keybindings.json`, `snippets/`, and `extensions.txt` as the daily dotfiles source of truth.

## Daily Workflow

After changing Neovim or VS Code settings locally, refresh this repository:

```sh
./scripts/sync-from-local.sh
git status
git diff
git add .
git commit -m "Update editor config"
```

## Restore On A Machine

From the repository root:

```sh
./scripts/install-to-local.sh
```

The install script backs up existing local paths before replacing them. Backup names include a timestamp, for example:

```text
~/.config/nvim.backup.20260629160000
settings.json.backup.20260629160000
keybindings.json.backup.20260629160000
snippets.backup.20260629160000
```

## Restore VS Code Extensions

Make sure the `code` command is available, then run:

```sh
xargs -n 1 code --install-extension < vscode/extensions.txt
```

On macOS, enable the command from VS Code with:

```text
Command Palette -> Shell Command: Install 'code' command in PATH
```

## Import VS Code Profiles

If this repository contains exported profile files under `vscode/profiles/`, import them through VS Code:

```text
Profiles -> Import Profile... -> Select File...
```

Profile import/export is a VS Code UI workflow. The `code` CLI can open a workspace with a profile name, but it does not replace the manual `.code-profile` export step.

## Notes

- Review `git diff` before committing, especially after changing VS Code settings.
- Do not add VS Code `globalStorage`, `workspaceStorage`, `History`, `logs`, or `sync` directories.
- Do not commit secrets, tokens, local API keys, or machine-specific absolute paths unless they are intentional.
- If Neovim plugins generate local state under `nvim/`, add those paths to `.gitignore` before committing.
- Treat `.code-profile` files as optional snapshots, not the main daily sync mechanism.
